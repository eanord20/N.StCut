# NStCut v1.0 — Implementation Plan (Master)

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans`. Execute subsystem plans in the order below. Each subsystem ends with a testable deliverable.

**Goal:** Build a WPF .NET 8 desktop app that reads DXF part contours (bounding-box for MVP), nests parts on sheets with grain/rotation constraints, and exports per-sheet DXF files plus a DOCX report.

**Architecture:** Solution split into `NStCut.Core`, `NStCut.Dxf`, `NStCut.Nesting`, `NStCut.Reports`, and `NStCut.App`. Core holds domain models and contracts; `Nesting` implements `INestingEngine` (MVP = bounding-box shelf packing, v1.1 = polygonal NFP); UI is a thin WPF shell over ViewModels.

**Tech Stack:** .NET 8, WPF, MaterialDesignThemes.Wpf, netDxf, Xceed.Document.NET, System.Text.Json, xUnit (tests).

## Global Constraints

- Target framework: `net8.0` for libraries, `net8.0-windows` for WPF.
- All dimensions are in **millimeters**.
- Default `PartGapMm = 5.0` and `SheetMarginMm = 5.0`, never hardcoded in logic.
- Localization resources only **EN/UA**; Russian resources are forbidden.
- DXF-to-part matching is by **filename only**, case-insensitive, whitespace normalized.
- No magic numbers/colors in logic or UI — use `AppConstants`, `NestingOptions`, `AppTheme.xaml`.
- No secrets or local paths committed; `.gitignore` must cover `bin/`, `obj/`, `.vs/`, `*.user`.
- Every public service lives behind an interface (`INestingEngine`, `IDxfGeometryService`, etc.).
- Each task ends with `dotnet build` and a commit.
