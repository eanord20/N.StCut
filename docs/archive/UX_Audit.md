# UX/UI аудит N.StCut

Аудит текущего интерфейса приложения N.StCut (WPF, .NET 8, MVVM, MaterialDesignInXamlToolkit) с точки зрения Senior UX/UI Designer с опытом проектирования профессиональных CAD/CAM приложений (Inventor, SolidWorks, AutoCAD, Fusion 360). Аудит не затрагивает бизнес-логику и не предлагает новых функций — только оценку и улучшение UX/UI существующего функционала.

## 1. Общая оценка: 5 / 10

Приложение функционально и построено по аккуратному MVVM-паттерну с рабочими сценариями (импорт деталей → материалы → поиск файлов → раскрой → экспорт). Но визуально это "конструкторский" интерфейс уровня внутреннего инструмента, а не production-grade инженерное ПО:

- нет тёмной темы (используется MaterialDesign **Light**, хотя целевая ОС — Windows 11, где инженерные CAD-приложения работают преимущественно в тёмной теме);
- слабая визуальная иерархия — все блоки выглядят одинаково;
- непоследовательные стили кнопок;
- отсутствуют иконки — все команды только текстовые;
- неполная локализация — часть UI жёстко на английском независимо от выбранного языка;
- нет индикации длительных операций (раскрой может быть небыстрым).

При этом ядро взаимодействия (инлайн-редактирование в таблице, drag&drop, группировка по материалу, undo) сделано разумно и не требует переделки логики — только оформления.

## 2. Основные проблемы

### 2.1 Тема и визуальный стиль
- Жёстко подключена только `MaterialDesignTheme.Light.xaml` (`App.xaml`) — тёмной темы нет вообще, переключателя тоже нет.
- Кнопка "Nest/Розкрій" использует `MaterialDesignRaisedButton`, все остальные кнопки — плоский `AppButtonStyle` с рамкой. Единственный элемент с акцентным стилем визуально теряется в общем ряду с второстепенными кнопками экспорта.
- Карточки-контейнеры (`Border` с `MaterialDesignCardBackground`) визуально идентичны для совершенно разных по смыслу блоков (пути, параметры раскроя, статистика, таблица деталей, кнопки действий) — нет заголовков секций, нет визуального разделения "настроек" от "данных" и "результата".

### 2.2 Иконки и обозначения
- Ни одна кнопка не имеет иконки — все команды (Nest, Export DXF, Export Report, Undo, Add Row, Delete Row, Find Files, Import Excel, Paste, Materials, Open DXF, Open Report) распознаются только по тексту. Для инженерного ПО, где кнопки нажимаются десятки раз в смену, это увеличивает когнитивную нагрузку и время реакции.
- Библиотека `MaterialDesignThemes.Wpf` уже подключена и содержит `PackIcon` — то есть возможность добавить иконки существует без новых зависимостей, но не используется.

### 2.3 Локализация
- `LocalizationService` поддерживает en/ua, но покрывает только часть строк главного окна (меню, лейблы, кнопки, заголовки колонок, статистика).
- Полностью не локализованы: `MaterialsWindow.xaml` ("Library", "In project...", "Add", "Delete", "Up", "Down"), `SheetPreviewWindow.xaml` ("Sheet Preview", "Sheet {0}", "utilization"), `CandidateSelectWindow.xaml` ("Select DXF file", "Several files match..."), все `ToolTip` (например "Click to make this material the active paste target"), все `ContextMenu` пункты строки таблицы ("Find file", "Select DXF manually", "Resolve ambiguous", "Delete row"), заголовки `MessageBox` ("Nesting error").
- Итог: при выборе украинского языка часть интерфейса всё равно остаётся на английском — ломается целостность локализации.

### 2.4 Визуальная иерархия и статус-индикация
- Блок статистики (Total/Found/NotFound/Ambiguous) — обычный текст без цветового кодирования; в реальной работе именно "Not Found" и "Ambiguous" должны сразу привлекать внимание (сейчас требуется вчитываться в цифры).
- Кнопка статуса строки (DataGridTemplateColumn "Status") — это `Button` без обводки/фона (`Background="Transparent" BorderThickness="0"`), выглядит как обычный текст, из-за чего не очевидно, что по нему можно кликнуть для резолва.
- Нет обозначения "текущего шага" процесса — пользователь должен сам понимать порядок: указать пути → материалы → вставить детали → найти файлы → задать параметры → раскроить.

### 2.5 Перегруженность таблицы деталей
- `DataGrid` содержит 10 разнородных колонок: порядковый номер, чекбокс "Вкл", текст, текст (тянущийся), составной template-степпер (кнопки -/+ и TextBox количества), текст пути к файлу, ComboBox материала, ComboBox текстуры, чекбокс поворота, кнопка статуса. Такая плотность интерфейса требует более чёткой визуальной сетки/выравнивания (шрифты, паддинги ячеек), иначе таблица выглядит "шумной".
- Группировка по материалу реализована через кликабельный `Expander`-заголовок группы, но визуально не отличается от обычной строки заголовка — не сразу понятно, что это интерактивный элемент выбора активного материала для вставки.

### 2.6 Длительные операции и обратная связь
- `NestCommand` не имеет индикатора занятости/прогресса — при большом количестве деталей UI может "зависнуть" без визуальной обратной связи, кроме текста в статус-баре после завершения.
- Ошибки показываются через стандартный `MessageBox.Show` (несколько операций, без единого стиля с приложением — MaterialDesign имеет свои диалоги, которые не используются).

### 2.7 Несогласованность окон между собой
- `MaterialsWindow` и `SheetPreviewWindow` используют MaterialDesign-темизированные элементы (`DynamicResource` фоны), а `CandidateSelectWindow` — полностью "голый" WPF (`ListBox`, обычные `Button` без стиля, кроме `AppButtonStyle` на кнопках OK/Cancel) — визуально выглядит как чужеродное диалоговое окно из другого приложения.
- `MaterialsWindow`: таблицы `LibraryGrid`/`ProjectGrid` не используют `PartRowStyle`-подобную стилизацию строк (нет чередования, нет единой типографики с главным окном).

### 2.8 Соответствие профессиональному CAD/CAM UX
Чего не хватает по сравнению с Inventor/SolidWorks/Fusion 360:
- Единой командной панели (Ribbon/ToolBar) с логической группировкой команд по задачам, а не по случайному расположению в карточках.
- Иконографики с общепринятой семантикой (дискета — сохранить, папка — открыть, стрелка назад — undo и т.п.).
- Тёмной темы как базовой (все перечисленные приложения по умолчанию тёмные на Windows).
- Явного отображения горячих клавиш в меню/тултипах.
- Индикатора состояния длительной операции (прогресс-бар/busy cursor) для раскроя.

## 3. Что уже сделано хорошо

- Чёткое разделение View/ViewModel/Command, единый `RelayCommand`, реактивные `CanExecute` (например, `NestCommand` активен только при `CanNest()`).
- Инлайн-редактирование прямо в таблице (количество через степпер +/-, материал и текстура через ComboBox, статус — кликабельная кнопка) — сокращает число кликов и переключений контекста для инженера.
- Группировка деталей по материалу непосредственно в рабочей таблице, с возможностью сделать материал "активным" одним кликом — удобный шорткат для быстрого ввода.
- Drag & Drop реализован в двух местах (перенос строк между секциями материалов в главной таблице, перенос материалов между библиотекой и проектом) — снижает количество вспомогательных диалогов.
- Undo для операций с таблицей.
- Статус-бар с текстовым отчётом о последней операции.
- Явные, поясняющие комментарии в XAML/коде (например, почему `AppButtonStyle` подключён точечно, а не как implicit-стиль) — хорошая инженерная культура, которая упрощает будущие изменения.
- Поддержка двух языков интерфейса с сохранением выбора между сессиями (через `AppSettingsService`).
- Персистентность пользовательских путей и параметров раскроя между запусками.

## 4. Предлагаемая структура окон

Функциональность и набор окон не меняются — 4 окна остаются, но перекомпоновываются:

1. **MainWindow** — вводится явное зонирование вместо одинаковых карточек:
   - Верхняя объединённая **командная панель (ToolBar)** с иконками, сгруппированная по смыслу: `Файл` (Open/Save project) | `Данные` (Find Files, Paste, Import Excel, Materials) | `Раскрой` (Nest, Export DXF, Export Report) | `Вид` (тема, язык).
   - Секция **"Источник/назначение"** — пути поиска/сохранения (без изменений в логике, только заголовок и выравнивание).
   - Секция **"Параметры раскроя"** — отступ от края, зазор между деталями.
   - Акцентированная **строка статуса поиска файлов** — Found/NotFound/Ambiguous в виде цветных бейджей, а не простого текста.
   - Секция **"Детали"** — чипы материалов + таблица (без изменения колонок/данных, но с более чёткой типографикой заголовков и границ).
   - Нижняя панель действий (Nest/Export) — с единым акцентным стилем только для главного действия (Nest), остальные — вторичные кнопки с иконками.
   - Статус-бар внизу — без изменений по смыслу.
2. **MaterialsWindow** — тот же двухпанельный макет (библиотека ⇄ проект), но со стилизацией таблиц в духе главного окна (чередование строк, единая типографика), заголовки колонок с иконками сортировки не нужны (не меняем поведение).
3. **CandidateSelectWindow** — привести к общей дизайн-системе приложения (тема, шрифты, отступы, стиль кнопок), сохранив тот же список/OK/Cancel.
4. **SheetPreviewWindow** — добавить панель инструментов над канвасом (масштаб, список неразмещённых деталей рядом), не меняя способ отрисовки самого раскроя.

Отдельно — вводится **переключатель темы Light/Dark** с сохранением выбора между запусками (по аналогии с уже существующим переключателем языка `MenuLanguage`/`SetLanguageCommand` и `AppSettingsService.Culture`), и **иконки на кнопках** через уже подключённый `PackIcon` (MaterialDesignThemes.Wpf) — без новых NuGet-зависимостей.

Правки после ревью (v3):
- **Верхній блок — 2 колонки**: зліва тулбар (**3 рядки кнопок, фіксована ширина колонки**), справа — шляхи пошуку/збереження + стан пошуку файлів (**3 рядки, гнучка ширина `*`**) — блоки вирівняні по висоті.
- **Тулбар розбитий на 3 групи-рядки з горизонтальними розділювачами** відповідно до алгоритму роботи, а не випадкового порядку:
  1. Row 1 — **наповнення таблиці**: Матеріали → Вставити ▾ (сплит-кнопка: "Вставити з буфера" + "Імпорт з Excel", дві наявні команди об'єднані в один дропдаун, щоб вкластися у фіксовану сітку 3×3) → Знайти файли.
  2. Row 2 — **формування файлів**: Розкрій (Nest) → Export DXF → Export звіту.
  3. Row 3 — **останні дії**: Відкрити DXF → Відкрити звіт → Очистити*.
- Команди Nest/Export/Undo/Add/Delete/Файл вручну **не дублюються** — живуть тільки в тулбарі (Row 1–3) або в панелі інструментів таблиці "Деталі", без повторення в нижній частині вікна.
- **"Стан пошуку файлів" повернутий у верхню видиму зону** (Row 3 правої колонки) як акцентний блок бейджів — не захований у загальний статус-бар унизу.
- Прибраний зайвий порожній розділювач одразу під меню.
- **Параметри розкрою** (відступ від краю, зазор між деталями) — як і раніше, у випадаючому меню "Розкрій ▾" (popup з двома полями), окремої картки в тілі вікна немає.
- Наповнення таблиці деталей (колонки, ширини, поведінка) — без змін.

### Пропозиції поза поточним обсягом (потребують окремого рішення)

- **"Очистити" (повне очищення списку деталей)** — нова бізнес-функція, якої немає в `MainViewModel` (немає `ClearAllCommand`). У макеті позначена окремо (`*`), включена на прохання користувача, але:
  - потребує реалізації `ClearAllCommand` у `MainViewModel`;
  - як деструктивна операція повинна підтверджуватись через `MessageBox` (Yes/No) перед виконанням;
  - бажано інтегрувати з наявним стеком Undo, щоб очищення можна було скасувати однією командою "Undo", як і інші операції з таблицею.
  - Це не UI-оформлення, а нова функція — реалізація виходить за межі UX/UI-документів і потребує окремого технічного рішення/задачі.

## 6. Список изменений по приоритету

### Critical
1. Добавить тёмную тему и **переключатель Light ⇄ Dark** с сохранением выбора (аналогично существующему переключателю языка + `AppSettingsService`).
2. Унифицировать стиль кнопок (единый `AppButtonStyle` для всех второстепенных действий; отдельный, осознанно применяемый акцентный стиль только для одного главного действия на экране — "Nest").
3. Визуально акцентировать статистику Found/NotFound/Ambiguous (цветные бейджи вместо простого текста).
4. Привести `CandidateSelectWindow` к общей дизайн-системе приложения (тема, шрифты, стиль кнопок).

### Important
1. Добавить иконки на командные кнопки через `PackIcon` (MaterialDesignThemes.Wpf, уже подключён).
2. Ввести заголовки секций на главном окне (визуальное зонирование процесса).
3. Индикатор занятости (busy state/курсор или прогресс) на время выполнения `NestCommand`/экспорта.
4. Полная локализация: тултипы, пункты `ContextMenu`, заголовки `MessageBox`, весь текст `MaterialsWindow`, `SheetPreviewWindow`, `CandidateSelectWindow`.
5. Выровнять стилизацию `DataGrid` в `MaterialsWindow` со стилем главной таблицы.

### Nice to have
1. Отображать горячие клавиши в пунктах меню/тултипах.
