# UI Design System — N.StCut

Финальная концепция интерфейса на основе `docs/UX_Audit.md`. Документ описывает **только** визуальную концепцию (карту экранов, wireframe, метрики, токены, компоненты) — код и бизнес-логика не меняются, новых функций не вводится.

---

## 1. Карта экранов

```
                         ┌─────────────────────┐
                         │      MainWindow      │  (root, единственное окно верхнего уровня)
                         │  1280×720 / Maximized│
                         └─────────┬─────────────┘
             ┌───────────────┬─────┴───────┬───────────────────┐
             │               │             │                   │
      "Матеріали"      "Статус"→клік   "Розкрій" (Nest)   Файл → OpenFileDialog /
     OpenMaterialsCommand SelectAmbiguous  NestCommand →   FolderBrowserDialog /
             │           File/SelectFile    (после успеха)  SaveFileDialog
             ▼               │Manually            │           (системные, не кастомизируются)
   ┌───────────────────┐     ▼             ▼
   │  MaterialsWindow   │ ┌───────────────────────┐   MessageBox (ошибки: "Nesting error")
   │  модальное, 920×520│ │ CandidateSelectWindow  │   (системный, не кастомизируется в XAML)
   └───────────────────┘ │ модальное, 500×300      │
                          └───────────────────────┘
                                                     ┌───────────────────────┐
                                              Nest → │  SheetPreviewWindow     │
                                              (опц.) │  немодальное?, 900×600  │
                                                     └───────────────────────┘
```

**Точки входа:**
- `MaterialsWindow` — кнопка "Матеріали" в тулбаре главного окна.
- `CandidateSelectWindow` — контекстное меню строки ("Resolve ambiguous"/"Select DXF manually") или клик по ячейке "Статус" при `Ambiguous`.
- `SheetPreviewWindow` — после успешного выполнения `NestCommand` (если предусмотрен показ результата) либо отдельной кнопкой "Перегляд".
- Системные диалоги (`OpenFileDialog`, `FolderBrowserDialog`, `MessageBox`) вызываются из `BrowseSearchPathCommand`, `BrowseOutputPathCommand`, `SelectFileManuallyCommand`, ошибок `NestCommand` — их внешний вид не кастомизируется (ОС), но подписи внутри (заголовки MessageBox) должны быть локализованы согласно аудиту.

**Модальность:** все три вспомогательных окна — модальные диалоги поверх `MainWindow` (текущее поведение сохраняется). Единственное окно верхнего уровня — `MainWindow`.

Grid.RowDefinitions (сверху вниз): Menu(Auto) → Card1 "Тулбар+шляхи" (Auto, 2 колонки: тулбар `Auto`(фіксована ширина) / шляхи+статус `*`(гнучка ширина), обидві колонки по 3 внутрішні рядки з горизонтальними розділювачами між групами) → Card2 "Деталі" (*, растягивается) → StatusBar(Auto). Card2 (таблица деталей) — единственная строка с `Height="*"`, все остальные `Auto`.

**Правки после ревью (v3):**
- **Верхний блок объединён в одну карточку с 2 колонками**, обе по 3 внутренние строки (гармоничны по высоте):
  - Левая колонка (**фиксированная ширина**) — тулбар, 3 группы-строки с горизонтальными разделителями между ними:
    1. Row 1 — наполнение таблицы: Матеріали → Вставити → Знайти файли.
    2. Row 2 — формирование файлов: Розкрій (Nest) → Export DXF → Export звіту.
    3. Row 3 — последние действия: Відкрити DXF → Відкрити звіт → Очистити*.
  - Правая колонка (**гибкая ширина `*`**) — пути и статус:
    1. Row 1 — путь поиска DXF.
    2. Row 2 — путь сохранения.
    3. Row 3 — **"Стан пошуку файлів"** (бейджи Found/NotFound/Ambiguous) — возвращены в верхнюю видимую зону, не в статус-бар.
- Убран лишний пустой разделитель сразу под меню.
- Команды Nest/Export/Undo/Add/Delete/Файл вручну — только в тулбаре или в панели инструментов "Деталі", без дублей в других местах окна.
- Параметры раскроя (отступ от края, зазор между деталями) — по-прежнему в меню "Розкрій ▾" (popup с двумя полями), отдельной карточки в теле окна нет.
- Наполнение таблицы деталей — без изменений.

## 3. Размеры и расположение панелей

### Окна (текущие → без изменений, зафиксировано)
| Окно | Размер | Модальность |
|---|---|---|
| MainWindow | 1280×720, стартует Maximized | Top-level |
| MaterialsWindow | 920×520 | Modal |
| SheetPreviewWindow | 900×600 | Modal |
| CandidateSelectWindow | 500×300 | Modal |

### MainWindow — структура строк (Grid.RowDefinitions, ревизия v3)
| Row | Содержимое | Height |
|---|---|---|
| 0 | Menu (+ пункт "Розкрій ▾" с параметрами отступа/зазора) | Auto |
| 1 | Card: тулбар (кол. 1, `Auto`, фикс. ширина) + пути/статус (кол. 2, `*`) — обе по 3 внутренние строки | Auto |
| 2 | spacer | 12 |
| 3 | Card: чипы материалов + вспомогательные кнопки таблицы (Undo/Add/Delete/Файл вручну) + DataGrid деталей | * (растягивается) |
| 4 | spacer | 6 |
| 5 | StatusBar | Auto |

Изменения относительно версии v2:
- Тулбар и блок путей объединены в **одну карточку с 2 колонками**, вместо отдельной строки ToolBar + отдельной строки с двумя карточками путей/статуса — визуально компактнее по вертикали.
- Тулбар теперь **3 строки × фиксированная ширина колонки** (а не 1 строка на всю ширину), с горизонтальными разделителями между строками-группами (наполнение / формирование файлов / последние действия).
- **"Стан пошуку файлів" возвращён в верхнюю видимую зону** — это Row 3 правой колонки (пути+статус), а не отдельная карточка и не статус-бар внизу.
- Убран лишний пустой разделитель сразу под меню (был в промежуточном варианте).

### Ширины колонок DataGrid деталей (сохраняются без изменений)
| # | Колонка | Width | Тип |
|---|---|---|---|
| 1 | # | 44 | Text, readonly |
| 2 | Вкл | 44 | CheckBox |
| 3 | Номер | 140 | Text |
| 4 | Назва | * (min 200) | Text |
| 5 | К-ть | 110 | Template (−/значение/+) |
| 6 | DXF файл | 240 | Text, readonly |
| 7 | Матеріал | 160 | Template (ComboBox) |
| 8 | Текстура | 130 | ComboBox |

### Toolbar (ревизия v3) — грид 3×3, без дублей в теле окна
- Размер ячейки кнопки: высота 28px, фиксированная ширина колонки (одинаковая для всех 3 столбцов грида).
- **3 строки, разделённые горизонтальным `Separator`** (1px, `MaterialDesignDivider`) между строками-группами — группировка по этапу рабочего процесса, а не по типу операции:

| Row | Группа | Кнопки |
|---|---|---|
| 1 | Наповнення таблиці | Матеріали → **Вставити ▾** (сплит-кнопка/дропдаун с двумя пунктами: "Вставити з буфера" = `PasteFromClipboardCommand`, "Імпорт з Excel" = `ImportExcelFileCommand`) → Знайти файли |
| 2 | Формування файлів | Розкрій (Nest, акцент/Primary) → Export DXF → Export звіту |
| 3 | Останні дії | Відкрити DXF → Відкрити звіт → Очистити* (новая функция, вне скоупа — см. раздел ниже) |

  Примечание по Row 1: `PasteFromClipboardCommand` и `ImportExcelFileCommand` — два существующих отдельных способа заполнить таблицу данными. Чтобы уложиться в фиксированную сетку 3×3 без добавления 4-й колонки, они объединены в одну **сплит-кнопку с выпадающим списком** ("Вставити ▾"), а не удалены — это визуальная группировка двух смежных по смыслу команд, поведение обеих команд не меняется.
- Команды Open project / Save project остаются в меню "Файл" (не в тулбаре) — это разовые/редкие операции, а не часть повторяющегося рабочего цикла.
- Переключатель темы и языка — в меню (Row 0 окна), не в тулбаре, т.к. переключаются редко (не каждый рабочий цикл).

## 4. Система отступов, типографика, иконки

### 4.1 Spacing scale
Текущие значения в XAML используют 4/6/8/12 px без единой системы (`CardPadding=8`, `SmallMargin=6`, spacer-строки Grid `6`, паддинги кнопок `10,4`). Предлагается зафиксировать единую шкалу, кратную 4:

| Токен | Значение | Использование |
|---|---|---|
| `Spacing.XS` | 4px | Внутренние отступы компактных элементов (иконка-текст в кнопке) |
| `Spacing.S` | 8px | Паддинг карточек (`CardPadding`), отступы между полем и лейблом |
| `Spacing.M` | 12px | Отступы между карточками (замена части `6px` spacer-строк на более воздушную сетку) |
| `Spacing.L` | 16px | Отступы вокруг основных секций/полей окна |
| `Spacing.XL` | 24px | Внешние поля окна (`Grid Margin` на уровне Window) |

### 4.2 Типографика
Базовый шрифт — системный (Segoe UI, наследуется от WPF/ОС), новые шрифты не добавляются (нет причин вводить внешнюю зависимость).

| Роль | Размер | Начертание | Пример |
|---|---|---|---|
| `Type.WindowTitle` | 13px (системное, из заголовка окна) | Regular | Заголовок окна ОС |
| `Type.SectionHeader` | 14px | SemiBold | "ДЖЕРЕЛО / ПРИЗНАЧЕННЯ", "ПАРАМЕТРИ РОЗКРОЮ" |
| `Type.Label` | 13px | Regular | "Папка пошуку DXF", "Відступ від краю листа, мм" |
| `Type.Body` / DataGrid ячейка | 13px | Regular | Значения таблицы |
| `Type.Caption` / статус-бар, tooltip | 12px | Regular | Статус-бар, подсказки |
| `Type.Badge` | 12px | SemiBold | Бейджи Found/NotFound/Ambiguous |

Это соответствует уже заданным в `AppTheme.xaml` значениям (`DefaultFontSize=13`, `Menu FontSize=12`) — не меняются, а формализуются в систему ролей.

## 6. UI Kit

### 6.1 Кнопки
| Вариант | Назначение | Стиль |
|---|---|---|
| **Primary** | Единственное главное действие экрана (Nest, OK) | Заливка `Accent`, текст белый/`TextPrimary` на тёмном, `CornerRadius=4`, `Padding=12,6`, `MinHeight=30`, иконка+текст |
| **Secondary** (текущий `AppButtonStyle`) | Все прочие действия (Export, Undo, Add/Delete Row, Browse...) | Прозрачный/`SurfaceElevated` фон, `BorderBrush=Divider`, `BorderThickness=1`, `Padding=10,4`, `MinHeight=26`, иконка+текст |
| **Icon-only** | Компактные действия в ячейках (степпер +/−, статус) | Без фона/рамки в покое, `Padding=0`, размер под ячейку (24×24), фон `SurfaceElevated` при hover |
| **Danger** | Удаление (Delete Row, Delete from library) | Как Secondary, но `BorderBrush`/иконка в `Dark.Error`/`#C62828` (light) |

Состояния (все варианты): `Default` → `Hover` (фон/граница светлее на ~8%) → `Pressed` (темнее на ~8%) → `Disabled` (`opacity 0.4`, `TextDisabled`).

### 6.2 Таблицы (DataGrid)
- Высота строки: 28px (текущая, неявно через `MinHeight` контролов внутри ячеек — фиксируется как стандарт).
- Паддинг ячейки: `6,2` (по горизонтали/вертикали).
- Заголовок таблицы: фон `SurfaceElevated`, текст `Type.Label` SemiBold, высота 30px.
- Группировка (`GroupItem`/`Expander`): заголовок группы — кликабельная кнопка на всю ширину, фон `Dark.Divider`/`MaterialDesignDivider` (как сейчас), но с добавлением иконки `ChevronDown`/`ChevronRight` слева от названия материала — чтобы явно читалось как интерактивный элемент.
- Строка с ошибкой (`IsDuplicateNumber`): рамка 2px `DuplicateNumberBrush` (без изменений).
- Чередование строк: не вводится (риск конфликта с текущей раскраской по статусу — статус важнее чередования).

- Используются в блоке "Стан пошуку файлів" (Found/NotFound/Ambiguous) и в колонке "Статус" таблицы деталей (замена текущей плоской кнопки-текста на бейдж, сохраняя кликабельность для резолва).

## 7. Предложения вне текущего скоупа (требуют отдельного решения)

В ходе обсуждения макета MainWindow в тулбар (Row 3, "Останні дії") добавлена кнопка **"Очистити"** — полная очистка списка деталей. Это включено в wireframe по прямому запросу, но фиксируется отдельно, так как это **не UI-оформление, а новая бизнес-функция**:

- В текущем `MainViewModel` нет соответствующей команды (`ClearAllCommand` отсутствует; ближайший аналог — `DeleteSelectedRowsCommand`, который удаляет только выбранные строки).
- Как деструктивная операция над всем проектом, она должна подтверждаться через `MessageBox` (Yes/No) перед выполнением.
- Рекомендуется интегрировать с существующим стеком Undo (`UndoCommand`/`_undoStack`), чтобы очистку можно было отменить одной командой "Undo", как и остальные операции с таблицей.
- Иконка-кандидат: `PackIconKind.TrashCanOutline` (или `DeleteSweepOutline`, если нужно визуально отличать от "Delete Row").

Реализация этой функции — отдельная задача (изменение `MainViewModel`/добавление команды), выходящая за рамки UX/UI-документов. Здесь она зафиксирована как согласованное пожелание к макету, но не как готовая к реализации спецификация.
